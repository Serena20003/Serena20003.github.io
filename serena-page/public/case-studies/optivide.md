# Context

Optivide is an active product build where I contribute to a cross-platform mobile app backed by Google Cloud services. The work sits in that important middle ground between speed and rigor: features need to move quickly, but the product and API surface still have to stay stable enough for the team to build on.

# What I owned

I own user-facing React Native work and contribute to the spec-first workflow around the backend contract layer. In practice, that means shaping feature behavior in the app, validating the API contract early, and using AI-assisted review and implementation loops to keep delivery fast without lowering the quality bar.

# Constraints

- Product requirements were still evolving quickly
- Frontend work needed to fit an established Express route-controller-service architecture
- Shipping speed mattered, but one-off patches would have made the codebase harder to extend

# Technical approach

I build within a typed React Native surface and work against backend contracts as early as possible. That reduces rework, keeps the mobile and API layers aligned, and makes implementation decisions easier to review as a team.

> The main goal has been to move quickly without creating “temporary” code that becomes permanent debt a week later.

I also rely on structured pull request review habits and GitHub Actions checks so integration issues get caught before they spread across the app.

# Outcome

The result is a more dependable shipping process for mobile features: faster iteration, clearer boundaries between frontend and backend work, and code that is easier for teammates to review, reason about, and extend.
